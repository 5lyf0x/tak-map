TAK Map v1.4.0-i643 Internal Release Validation
================================================
Date: 2026-09-03
Baseline: TAK Map v1.4.0-i642

Release scope
-------------
- Replaces i642's unsupported Mission /cot POST/PUT Shape update path with the native TAK Shape workflow proven live against OpenTAKServer 1.7.13.
- Preserves edited Shapes as their original native TAK drawing CoT objects (u-d-*; rectangle u-d-r), same Shape UID, same Mission destination metadata, and preserved raw style/detail metadata.
- Never converts a Shape into an EUD/self-position event, never substitutes the authenticated user/client UID for the Shape UID, and never collapses Shape geometry to the center point.
- Sends the native Shape over the authenticated per-user certificate SSL CoT transport.
- Requires exact edited geometry through GET /Marti/api/cot/xml/<uid>/all before Mission association. Historical same-UID public.cot existence is not a commit gate.
- Associates/refreshes the same UID in each existing Mission with PUT /Marti/api/missions/<mission>/contents and JSON {"uids":["<shape uid>"]}.
- Uses Mission /cot only for GET authoritative read-back; i643 does not POST or PUT to Mission /cot.
- Requires the same UID, same native u-d-* type, and edited geometry from every affected Mission before Save succeeds and Edit mode exits.
- Rectangle/polygon verification remains independent of cyclic starting vertex and winding direction within coordinate tolerance.
- If transport diagnostics, global read-back, Mission association, or Mission read-back do not confirm the edit, Edit mode remains active with the draft intact.
- Preserves the existing compact Shape editor: in-place fields, edit-only center translation handle, type-aware vectors, dynamic map-side dimensions, Center field, Notes last, half-width Save/Cancel, larger Save/Cancel labels, empty-map click protection, and silver/gray TAK Map controls.
